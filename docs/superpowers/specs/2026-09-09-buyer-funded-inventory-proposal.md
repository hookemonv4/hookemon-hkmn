# Buyer-funded inventory proposal

Status: proposed; not an authoritative requirements revision. The owner requested a launch with no creator-funded ETH seed. This proposal records the bounded contract behavior implementing that request; production inputs and provider acceptance remain unselected.

Replace the native-seed full-range-only constraint with: `seedCanonicalLiquidity` may mint the complete issued HKMN allocation with `amount0Max == msg.value == 0` into an explicitly selected valid range whose upper sqrt price equals live pool price and, for graph mode, the immutable token launch price. Positive-native legacy seeds retain their full-range constraint. Neither path changes the fixed supply, custody ownership, fee rates, allowance cleanup, exact debt funding, or solvency rules.

The range and price must be selected together before graph construction. No production tick, price, liquidity amount, supply change, creator allocation, or first-buy amount is proposed here. The existing fixed supply is preserved. Zero-native inventory requires maximal liquidity floor(stock * Q96 / priceSpan). Its mathematically unavoidable rounding remainder is transferred to the same permanent custody with no withdrawal function. Intentionally reduced liquidity is rejected. The entire supply stays locked across the position and custody; no creator or treasury allocation is added. Positive-native graph seeds retain the exact-consumption requirement. A finite range can exhaust inventory; this change does not guarantee unbounded fills or funds for selling before buyers have supplied ETH.

At the upper boundary the pinned Uniswap implementation charges only currency1 principal. Native currency0 supplied by later buys becomes available for sells; fee liabilities remain backed by ETH collected from those swaps. Sources: [Pool.modifyLiquidity](https://github.com/Uniswap/v4-core/blob/46c6834698c48bc4a463a86d8420f4eb1d7f3b75/src/libraries/Pool.sol), [DeltaResolver settlement](https://github.com/Uniswap/v4-periphery/blob/dce236d4e2057422d0791d9a973a58765eb46f65/src/base/DeltaResolver.sol).

The custom 10/40/250-basis-point route still requires a compatible Programmable server adapter. Local pinned-contract execution does not prove provider submission, preflight acceptance, deployment or on-chain readiness.

OPEN FACT: the production first-buy adapter must pre-settle actual buyer ETH before the swap callback. A standard post-settlement router fails on an empty PoolManager when the hook takes its fee. The pinned local tests prove failure rollback and the upstream MockV4Router wrapper executing pinned V4Router SETTLE, SWAP_EXACT_IN_SINGLE, TAKE_ALL actions proves a fully backed buy/sell round trip at fixture upper ticks zero and 60. Resolve this by verifying the same existing V4Router action ordering in the selected deployed router and provider adapter; neither forced pool ETH nor deferred unbacked fee accrual is an acceptable substitute.

The action order follows [pinned V4Router](https://github.com/Uniswap/v4-periphery/blob/dce236d4e2057422d0791d9a973a58765eb46f65/src/V4Router.sol). SETTLE uses the explicit buyer amount; SETTLE_ALL before the swap would observe zero debt and would not fund the fee. These fixture amounts and ticks are test inputs only.
