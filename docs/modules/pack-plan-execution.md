# Pack plan execution

The saved selection is an ordered list of pack codes and quantities. A new cycle captures it once, obtains exact unit and aggregate funding evidence and persists the plan together with its admission. Every following cycle uses the same saved selection until the operator edits it. Changes do not rewrite active cycles.

The public boundaries are `AutomatedCycleService.readPackPlan`, `buildAdmissionPlanner.plan({ cycleId, packPlan })`, admission `hookemon.policy-admission.v4`, and repository per-order intent/response methods documented in the cycle repository card. Purchase preparation binds all selected orders to the parent request digest. Mutation runs each order through the existing signer-policy and debit-bound checks, with its generated memos durable before signing. Reconciliation uses each pack's own admitted unit bound and never reports a partially generated plan as complete.

Generation moves from absent to durable intent to durable memo response, independently for each order. An intent without a response is uncertain and requires reconciliation; it is never automatically regenerated after restart. Generated memos reuse the existing finality/deadline recovery path. Unsupported multi-card fan-out, unavailable pack catalog entries, missing quote evidence, stale revisions and money-cap violations refuse before the dependent effect.

Run the focused policy-engine, automated-cycle-service, plan-order-events, plan-stage-compatibility and multi-pack-recovery Node tests. These tests use synthetic provider replies and isolated state; passing them does not authorize or prove mainnet execution. Operational recovery uses the existing cycle hold and quote-refresh commands, not an alternate dashboard authority or a reset of the selected plan.

A migrated empty plan admits no new live cycles. Existing v3 cycles retain their original policy digest rules: expanding or revoking their allowlist can still cause a safe policy refusal. Introduce new allowed packs after those legacy cycles finish; this implementation does not reinterpret their historical digests. V4 plan changes and allowlist expansion preserve the active plan, while an explicit allowlist revocation remains an immediate safety veto.
