# Pack plan execution

The saved selection is an ordered list of pack codes and quantities. A new cycle captures it once, obtains exact unit and aggregate funding evidence and persists the plan together with its admission. Every following cycle uses the same saved selection until the operator edits it. Changes do not rewrite active cycles.

The public boundaries are `AutomatedCycleService.readPackPlan`, `buildAdmissionPlanner.plan({ cycleId, packPlan })`, admission `hookemon.policy-admission.v4`, and repository per-order intent/response methods documented in the cycle repository card. The composition root binds `readPackPlan` only together with the production admission planner; a live composition without that planner (the Collector-only rehearsal) keeps its configured pack and never waits on the empty saved plan. Purchase preparation binds all selected orders to the parent request digest. A newly prepared single-pack order additionally binds `generation: { endpoint: 'generatePack', turbo: false }`, the approved non-turbo single-pack route; a multi-pack order keeps the batch `generateYoloPacks` route. A partially generated plan recorded before that binding resumes under its own recorded identity: the stage driver re-prepares the plan, and when the fresh request differs from the recorded parent digest only by the per-order `generation` binding (`legacyPlanPurchaseRequest`, verified by recomputing the digest), it continues with that original request and digest, so the remaining orders keep the batch route their identity was recorded with. A recorded digest that matches neither the fresh nor the legacy request still refuses with `plan purchase resume requires the original parent request digest`; the per-order uncertain-generation and admission checks apply unchanged on either path. Mutation runs each order through the existing signer-policy and debit-bound checks, with its generated memos durable before signing. Reconciliation uses each pack's own admitted unit bound and its own order's request time for the unresolved deadline, and never reports a partially generated plan as complete.

Generation moves from absent to durable intent to durable memo response, independently for each order. An intent without a response is uncertain and requires reconciliation; it is never automatically regenerated after restart. Generated memos reuse the existing finality/deadline recovery path. A partial plan resumes under its original parent request digest only after every generated prior order has durable terminal outcomes from per-memo reconciliation. A provider response alone cannot authorize the next order while signing or broadcast remains uncertain. Unsupported multi-card fan-out, unavailable pack catalog entries, missing quote evidence, stale revisions and money-cap violations refuse before the dependent effect.

Run the focused policy-engine, automated-cycle-service, plan-order-events, plan-stage-compatibility and multi-pack-recovery Node tests. These tests use synthetic provider replies and isolated state; passing them does not authorize or prove mainnet execution. Operational recovery uses the existing cycle hold and quote-refresh commands, not an alternate dashboard authority or a reset of the selected plan.

A migrated empty plan admits no new live cycles. Existing v3 cycles retain their original policy digest rules: expanding or revoking their allowlist can still cause a safe policy refusal. Introduce new allowed packs after those legacy cycles finish; this implementation does not reinterpret their historical digests. V4 plan changes and allowlist expansion preserve the active plan, while an explicit allowlist revocation remains an immediate safety veto.
