# Launch delivery

The delivery assembler snapshots the current native launch source and release bytes for coordination and review. It keeps compiler inputs, each inline Solidity source, the three artifacts, release records, package tools, requirements, owner inputs and the existing metadata image together. It reads no environment file, API key, wallet or runtime observation.

`assemble-launch-delivery.mjs --source WORKTREE --output NEW_DIRECTORY` creates a new directory atomically after rechecking every input. `--verify DIRECTORY --source WORKTREE` verifies all file hashes and detects changes in the source revision or package inputs. An existing output is never replaced. Refresh after another worker completes its changes; retain previous snapshots as evidence of their exact bytes.

The manifest records the source commit and the actual file bytes, including uncommitted inputs. Compiler source mismatch, inconsistent artifact settings, symlinks, unsafe paths, unexpected snapshot files and credential-like text are refused. The source tree is read twice before publication to detect concurrent edits. Runtime sizes and unresolved request fields are reported; null fields alone do not determine schema validity.

Every output is `PREPARATION_SNAPSHOT`, with `readyForPreflight: false`. Integrity is not compiler reproduction, an authenticated runtime observation, provider admission or wallet authorization. The assembler neither creates a new request nor upgrades a template to a signable launch. The final producer retains its original runtime-observation authority and financial inputs.

The official [4.1 launch workflow](https://programmable.market/docs/developers/custom-launch-quickstart) requires a complete pack configuration, `pack --config CONFIG --output launch.json --receipt receipt.json`, then `validate launch.json --config CONFIG`. V4 validation rebuilds the exact request from that configuration; validating only request shape does not establish readiness. Remote preflight, submission and the wallet signature remain separate operations. This delivery tool never changes the confirmed project fee agreement.

If verification reports `STALE`, assemble into a new directory from the completed source lane and rerun the applicable package checks. Do not edit snapshot bytes or reuse a previous admission response for a changed request. If assembly catches an in-progress upstream edit, wait for that worker's completion handoff before refreshing.

The selected HKMN icon is `release/phase3/metadata/hkmn-logo.png`, a lossless PNG encoding of the owner-supplied JPEG pixels. Its compressed image stream is re-encoded without changing the inflated image data, and ancillary metadata is excluded. The current delivery carries `metadata/input.json`, `metadata/project-metadata.json` and `metadata/project-image-artifact.json`; the official metadata builder binds the actual image bytes and immutable public URI there. Refresh those artifacts whenever image bytes change. The feasibility materialization directory retains its historical read-only candidate and is not the current branding input. The internal address-derivation draft retains its frozen icon schema. Icon validation does not establish request admission or DEX Screener publication.

## Official API input preparation

`node scripts/programmable/prepare-api-inputs.mjs --source <clean-source> --cli-root <verified-cli-4.1.0-package> --capabilities <captured-capabilities.json> --metadata <metadata-input.json> --output <new-directory>` prepares reusable inputs with the official chain descriptor, profile, source-bundle, metadata and image functions. The operator supplies the complete checksum-verified CLI release with its locked dependencies; the tool additionally pins the four entry-module hashes. It does not load credentials or make network calls.

The source is a clean Git worktree with a public GitHub origin and exact commit. Only the inline compiler source closure, Standard JSON, three artifacts, address manifest and selected image enter the source bundle. Top-level input bytes must match that commit; compiler sources must match their embedded bytes. Secret paths, linked sources, changed descriptors, overwritten outputs and outputs beneath the source are refused. The source and input bytes are rechecked before output creation. This subset is not the complete release tool inventory, and these checks do not reproduce compilation or prove public URL availability.

Outputs are provider-binding, source-origin, source-bundle, project-metadata, project-image-artifact and preparation-report JSON files. The report retains the exact result of the selected public profile-4.1 kernel check, a fresh public nonce and input hashes. An exact-kernel refusal applies only to that profile; other provider routes remain unassessed. No launch request, funding amounts, agent attestation or launch-intent hash is generated. `readyForPreflight` remains false because these inputs do not constitute a complete request. Recovery is a fresh output directory after correcting the named input; do not edit a previously generated package into an apparent approval.
