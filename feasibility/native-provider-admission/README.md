## Exact route and contract

The [official V4 OpenAPI](https://programmable.market/openapi/custom-launch-v4.1.json) defines `POST https://api.programmable.market/v4/chains/4663/custom-launches/preflight`, operation `preflightCustomLaunchV4`, with required `application/json` body `CustomLaunchCreateRequestV4`. Its 200 response is `CustomLaunchPreflightV2`, described as side-effect-free server-authoritative preflight. The bearer key needs `custom-launch:create` scope and chain 4663 access. This is a complete launch-request interface, not a separate economics-only probe. A 400 caused by missing fields would not answer whether the project model is admissible. A 200 must likewise be read for its actual findings, not treated as launch authorization.

The [official create schema](https://programmable.market/schemas/custom-launch/v4.1/create-request.json) requires all 22 root fields listed in `create-schema.json.required`, including `fundingPlan`. The request schema literal remains `programmable.custom-launch-create-request.v4` while its profile is 4.1.0. `input-create-request.snapshot.json` preserves the exact local draft bytes; `input-origin.json` records its source worktree HEAD and capture time. It is an uncommitted working-tree artifact, not a committed release or signable payload. `inspection.json` binds its hash and lists every proven direct violation. The inspection script intentionally does not claim complete JSON Schema validation, canonical hash verification, runtime reproduction, or provider simulation.

## Published economics and limits of this finding

Capabilities still requires a native platform fee of 20 bps / 2,000 ppm, rounded up per trade, on the gross native leg once per successful swap, **separate from creator and LP fees**, with exact kernel proof before wallet handoff. This does not match the project's approved inclusive 10/40/250-bps model. The guide requires an atomic initial buy worth at least USD 1 for funded 4.1 launches. The project currently authorizes a separate payable seed, not an added atomic buy. Neither policy has been silently incorporated into the request.

The schema explicitly supports `fundingPlan.launchMode = build-only` for local pack/preflight; it cannot obtain a launch permit and fresh create must reject it before persistence or signing. Therefore a genuinely complete, deliberately classified build-only request could obtain bounded preflight findings without selecting a funded launch. It would not prove admission of the intended separately seeded launch. This incomplete draft is neither such a valid request nor a funded request.

Public `GET https://api.programmable.market/v4/chains/4663/initial-buy-quote` can return the server's current minimum for the provider's alternative funded model. It cannot choose the owner's buy amount, minimum token output or gas cap. It is unnecessary to fill the current approved model and was not fetched. Captured readiness/public-write flags and broad structural coverage are service facts; coverage expressly does not authorize a caller request. No private exception, model acceptance, economics rejection, or selected funding ceiling is inferred.
