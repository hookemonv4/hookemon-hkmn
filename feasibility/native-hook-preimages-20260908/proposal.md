# Proposed acyclic issuance commitment contract

Status: proposed, not approved or implemented. This would clarify `REQ-provider-binding-3` and the two constructor fields. The coordinator must select and freeze exact schemas before any values are materialized. It is not a provider-required convention.

Option A is a two-stage commitment. Define immutable predeployment binding and runtime-authority documents, then separately bind the fully materialized deployment outcome. This retains the existing constructor equality guard while avoiding a fixed point. Option B is to obtain an authoritative preexisting integration formula with equivalent acyclic dependencies and reproduce it. Treating these fields as arbitrary owner-chosen nonce values is not supported by the current reproducibility requirement and would need an explicit semantic change.

For Option A, the proposed exact hash envelope is `keccak256(abi.encode(string domain, bytes32 documentSha256))`, where `documentSha256` hashes the exact UTF-8 canonical JSON bytes, object keys recursively sorted lexicographically, no insignificant whitespace, no trailing newline, no floating-point values, addresses lowercase hex, quantities decimal strings, and no unknown fields. Proposed domains are `HOOKEMON_NATIVE_ISSUANCE_BINDING_V1` and `HOOKEMON_NATIVE_ISSUANCE_RUNTIME_AUTHORITY_V1`. These names and algorithm are proposals, not recovered facts.

The binding document should contain its schema ID, chain identity, exact requirements content digest, provider protocol/version, immutable role addresses, native asset identity, token identity/economics, callback mask, pool fee/tick spacing, claim limits, rotation delay, and the digest of a separately immutable provider evidence record. Evidence must already exist before constructor materialization. It must exclude the hook address, hook salt search outcome, hook init-code hash, hook final runtime hash, full PoolKey pool ID, graph call hashes containing hook bytecode, provider intent signatures and its own digest. Token/custody addresses may be included only after their independent preimages are reproduced. No reference may indirectly reintroduce an excluded dependency.

The runtime-authority document should identify the exact official external provider deployment/runtime/ABI evidence (chain, address, source version, code hash, observation block and evidence artifact SHA-256), and the exact authority mechanism allowed to issue and attest the token. It must not claim that a caller-provided JSON record proves provider approval. Include custom-hook source/compiler/template evidence only through a separately defined deterministic artifact that does not embed the final constructor immutables; otherwise omit it here and bind it after construction. A template hash requires an explicit byte-normalization specification and independent test vectors before use.

Then compute the two constructor digests, encode constructor/init code, mine the permitted hook address, and derive complete pool and graph calls. A distinct final deployment record binds both predeployment digests to exact constructor bytes, hook salt/address/init-code hash, actual materialized runtime, pool ID, graph calls and any admitted provider intent/attestation. This final record is checked offchain under the release's existing approval boundary; it must not be fed back into the same constructor digests.

Required verification before adopting this proposal: deterministic canonicalization vectors, one independently computed positive envelope vector, a field-by-field mutation test, a dependency graph with no recursive content-address references, exact agreement between constructor and issuance plan/observation, and independent evidence/authority validation. Unknown provider identities remain unknown. Build-only preflight acceptance still would not admit a separately financed seed or approve launch economics.

Owner decision needed: approve a new preimage contract or provide the existing authority defining it. Routine calculation, serialization and testing can follow that decision without choosing economic values or manufacturing provider facts. This artifact does not select final/test deployment, seed principal, claim ceilings, or runtime authority.
