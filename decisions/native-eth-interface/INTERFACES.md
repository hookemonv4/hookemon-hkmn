Apply the accompanying revision 71 patch only after that baseline is integrated and the coordinator has verified authority for this exact native scope. ## Native proof and valuation producer contracts

Proposed `createNativePaymentProof` is an adapter-only producer, not an arbitrary JSON acceptance function. Retain the current RPC proof's process-local provenance discipline (as used by `isProcessRpcFinalizedErc20TransferProof`) with a native equivalent. Persisted proof is reauthenticated from bound RPC/release evidence on reconstruction.

The provider/source facts below constrain these proposed proof fields; they are not arbitrary emitter choices. Common native proof fields are `schema`, `kind` (`direct`, `hook-claim`, `relay-return`, `relay-refund`), `chainId`, `assetId`, `decimals`, `transactionHash`, `transactionDigest`, `blockNumber`, `blockHash`, `source`, `recipient`, `amountWei`, `calldataDigest`, `receiptStatus`, and `evidenceDigest`. Require success, canonical finality, exact persisted transaction binding, and once-only cycle/leg consumption. Direct proof additionally binds persisted signed bytes/hash and sender nonce. Gas usage/fee are separate cost evidence.

Hook-claim proof additionally binds `cycleId`, `hook`, `hookRuntimeHash`, `logIndex` and exact decoded ProcessClaimed fields, proving that this trusted implementation emits only after its successful value call. For the observed router cleanupNative route, Relay return/refund proof additionally binds `relayRequestId`, `sourceTxHash`, source finality, `emitter`, `runtimeHash`, `logIndex`, `providerBindingDigest`, decoded recipient/value and `innerCallSucceeded`. The observed source proof is pinned to provider evidence commit acce05b40340310ef76f86ea77ae23deaf5d1369, `docs/evidence/native-provider-20260908/verified-RelayRouterV3.sol.txt`, SHA-256 ec94f85dfe1a33b0fd5b05a3544a67ccdbb19dc8501b2f58cb960712063dcefa. Its cleanupNative calls reverting safeTransferETH before FundsMovement(from=router,to=recipient,currency=address(0),amount,metadata). Bind the exact event metadata to the authenticated request/order and require unique positive payment. SolverNativeTransfer alone is insufficient because receive() also emits it to the router itself. cleanupNativeViaCall emits no FundsMovement and is not admitted by analogy. A RelayCallExecuted identifier is a CallRequest struct hash, not automatically the order ID; outer success can coexist with allowed individual failures. The historical packet matches current/latest runtime to source, but finalized-checkpoint eth_getCode failed; require archive/runtime evidence at the actual payment checkpoint before treating this as live proof. A provider status pointer or event name alone remains insufficient. A missing proof remains unresolved and supplies no payout principal. No ending account balance difference or synthetic Transfer log is accepted.

`quote-usd-valuation.v1` fields: `schema`, `quoteDigest`, `requestDigest`, `quoteRequestId`, `sourcePath`, `amount` (the exact TypedAmount being valued), `amountMicroUsd`, `rounding` (`up` for costs/exposure, `down` for proceeds), `observedAtMs`, `validUntilMs`. Producers read `details.currencyIn.amountUsd` or `details.currencyOut.amountUsd` from the exact fetched quote and bind matching chain, currency and atomic amount; never accept unrelated caller-supplied valuation. Native cost basis is frozen at commitment. Additional unresolved liquid exposure requires fresh bound valuation; reconcile reservations against exposure so principal is counted once. Retain attributed purchase cost for held cards. A missing valuation refuses new risk while allowing observation and authorized recovery.

The official [Relay quote reference](https://docs.relay.link/references/api/get-quote-v2) documents amountUsd and exact native-value transactions. Its [EVM Depository reference](https://docs.relay.link/references/protocol/contracts/evm-depository) describes depositNative(address,bytes32). These interfaces do not prove the deployed return emitter, inner-call success behavior or this project's current executable route. Only decode depositNative when the observed pinned quote actually uses it; never replace an API payload with a guessed call.
