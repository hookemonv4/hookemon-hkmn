# ADR-0027: Collector production binding boundary, no live authority

## Status

Accepted on 7 September 2026. Owner approval reference: revision 68/S5r00647 on integration `39c1770a` (recorded by the coordinator; this document does not itself run the owner-authorize gate command). Owner's exact instruction to proceed: "Ja, diese Anbindung und den isolierten Volltest umsetzen."

## Context

`collector-production-frontier-review.md` found the production Collector purchase/buyback path fail-closed with no live binding authority, per `architecture/interfaces.json`'s `UNWIRED_OFFLINE_MODULE_ONLY` status for `collector-purchase-policy.mjs`. No buyback binding factory existed at all; `buyback.mjs` used only a raw, externally supplied canonical policy. The review proposed a bounded implementation: a narrow production binding registry, a distinct buyback binding factory, and isolated synthetic evidence through the real production code path -- without approving any live account, program, digest, or spend.

## Decision

- Add `packages/adapters/src/signing/collector-production-binding.mjs`: an immutable registry loader (`loadCollectorProductionBindingRegistry`) and resolver (`resolveCollectorProductionBinding`) keyed by `{authority, stage}`. Every entry is schema/digest-validated through the existing per-stage binding validators; an entry never supplies its own approval, only self-consistency between its bytes and its own `expectedDigest`.
- Add `packages/adapters/src/signing/collector-buyback-policy.mjs`: a distinct, fixed buyback binding schema and factory (`createCollectorBuybackPolicy`) built on the existing canonical transaction-policy decode/evaluate contract, with its own instruction sequence, cycle facts, and quote/minimum/refund binding. It does not extend or reuse the purchase binding schema, and it exposes no open/generic signing factory.
- The `live` authority identity is refused unconditionally, at both load and resolve time. No independently pinned live-authority mechanism exists anywhere in this codebase; a caller cannot grant itself live authority by choosing binding bytes, recomputing a matching digest, and labeling the result "live". No live registry entry, account, program, or digest is approved or added by this decision.
- The `synthetic-offline` authority resolves only after `assertCollectorOfflineExecutionBoundary` passes every one of its independent, composite checks together: production execution profile, no rehearsal configuration, the explicit authority selection, every actually-transport-read endpoint resolving to an explicit loopback URL, and `config.signer.keychain.isolatedChildSetup` being the exact object `createIsolatedKeychainChildSetup` returned (module-private `WeakSet` membership, never a value/shape match) with `config.signer.keychain.command` equal to that setup's own `command`, running the real live-signing protocol against it. No single one of these checks is accepted alone as isolation, and the Keychain identity is never a caller-chosen label or a hash of caller-supplied bytes -- only this module's own construction is ever trusted. `createIsolatedKeychainChildSetup({ directory })` fixes the real signer/wallet binaries and the isolated `security` fixture all from its own module root (never a caller-supplied path, command, or security backend), requires `directory` to be an absolute, non-symlinked real directory, refuses before any subprocess is spawned if the fixed store/record-log/pid paths inside it already exist as a symlink or other nonregular file (an absent path or an ordinary preexisting regular file both pass), reuses an existing ephemeral identity if one is already present at that root rather than minting a replacement on every launch, and writes a wrapper (via an atomic temp-file-then-`rename` replace) spawning that fixed path with a minimal, explicitly allowlisted child environment (`PATH` pinned to the running interpreter's own directory, plus exactly the isolated backend's fixed variables, never a spread of `process.env`). The returned setup carries a digest over the wrapper's own bytes, re-verified at every point of use, so a `WeakSet`-branded setup whose on-disk wrapper was edited after construction still refuses.
- `compose.mjs` and `environment.mjs` add narrow typed selection and attachment: `HOOKEMON_COLLECTOR_PRODUCTION_BINDING_AUTHORITY` (enum, "synthetic-offline" only), `HOOKEMON_COLLECTOR_PRODUCTION_BINDING_REGISTRY_PATH` (a JSON file read like any other config path this module reads -- the path grants no authority, only the digest-validated content does), and direct object injection of the registry itself (`config.collectorProductionBindingRegistry`, validated before attachment) -- never a raw policy blob or an operator-configurable path granting authority by itself. `environment.mjs` checks the authority selection first, before reading any credential-file-selector env var, refusing outright if `HOOKEMON_COLLECTOR_CRYPT_API_KEY_PATH` is set under `synthetic-offline`; under `synthetic-offline` it also requires the inline Collector/Relay credential values to equal the fixed `COLLECTOR_SYNTHETIC_API_KEY`/`RELAY_SYNTHETIC_API_KEY` sentinels and requires `HOOKEMON_COLLECTOR_SYNTHETIC_ROOT` (the isolated root the child setup will use). `isolatedChildSetup` is never an env var (an opaque branded object); the real `bin/hookemon-runner.mjs` entrypoint constructs it itself (`applySyntheticIsolatedChildSetup`, called from `buildComposition` once `readEnvironment` reports the `synthetic-offline` authority) and overlays it onto `env.signer.keychain` before composition -- no test-only manual overlay or in-process config surgery is needed to reach it. `bin/hookemon-runner.mjs`'s `compositionInput` forwards the environment-sourced registry, and the constructed `env.signer` itself, into the composed config.
- A small scoped `createLoopbackConfinedFetch` wrapper is threaded as `fetchImpl` into the Collector, Relay, and Solana RPC clients, and via viem's own `http(url, {fetchFn})` transport into all three Robinhood/EVM construction sites (primary client, `secondaryLogClient`, `archiveEvidenceClientFromConfig`) `compose.mjs` constructs for the `synthetic-offline` authority: it refuses a nonlocal request URL and refuses to silently follow a redirect response, since an already-loopback `baseUrl` alone does not stop a misbehaving local mock from handing a client an outward-pointing 3xx. `bin/hookemon-runner.mjs`'s own `chainBroadcastTransports` -- the actual already-signed-byte EVM/Solana broadcast clients, constructed independently of `compose.mjs`'s adapters -- threads the identical confinement into both under `synthetic-offline`. No EVM exception and no unconfined broadcast path.
- `purchase.mjs` and `buyback.mjs` add this registry as a second, mutually exclusive seam beside the existing Node-test-only fixture binding, resolved and immutably captured before the relevant provider call is ever awaited, from durable per-cycle/per-pack facts only. `buyback.mjs`'s cycle facts require the open stage to actually be `COMPLETE` (not merely present) and bind the sold pack to its recorded mint/memo/asset-kind for that exact pack index -- an absent asset kind is never defaulted to `spl` -- and to a freshly observed finalized current owner required to equal the configured operator and re-checked immediately before signing -- never a blind copy of configuration -- and cross-check the resolved binding's own proceeds mint/decimals against the configured settlement asset before any provider mutation.
- `signer.liveMode === true` is required, not refused, by the offline boundary: production's own non-dry-run rule already requires it, and it is not itself a network/credential isolation signal -- the authenticated wrapper and endpoint confinement around it are what make running the real live-signing protocol against the isolated backend safe.

## Alternatives

### Wait for real Collector provider evidence before writing any code

Pros: no synthetic binding shape to later reconcile against real provider bytes.

Cons: leaves the production purchase/buyback wiring boundary, registry contract, and offline-evidence boundary entirely unreviewed until that evidence exists, with no bounded way to exercise the real stage/custody machinery in the meantime.

Rejected: the owner approved building and proving the boundary now, against synthetic evidence, while leaving live values unapproved.

### Approve a real live binding entry as part of this task

Pros: would close the production gap the frontier review found.

Cons: no independently verified Collector program, account, co-signer, or instruction template exists yet; approving one now would be inventing production authority.

Rejected: out of scope. `architecture/interfaces.json`'s live-binding-status fields remain unapproved after this decision.

## Consequences

- The purchase and buyback stages can each be exercised end-to-end through the real production code path, including a genuine `readEnvironment` -> `compose` ordinary-CLI carrier, against an isolated, synthetic registry entry and a real, authenticated Keychain child. A focused test drives a real `bin/hookemon-wallet.mjs generate` and `bin/hookemon-keychain-signer.mjs` sign/probe round-trip through this exact boundary.
- Production composition still has no path to a resolvable live binding entry; purchase and buyback continue to refuse exactly as before whenever no fixture and no registry entry are configured.
- Full loopback mock servers for Collector/Solana/Relay/Robinhood, and the literal full-flow CLI proof driving a real purchase/buyback mutation against them, remain the N2 worker's scope; this decision's own tests exercise the config/registry/boundary/child plumbing feeding that graph, with provider adapters/network-identity injected the same way `compose.test.mjs` already does throughout (the Keychain child and, separately, a real loopback EVM redirect-refusal check, are not injected -- both run for real).
- A stage-level regression for a mismatched resolved-binding proceeds asset is now also covered, using the same real isolated child setup this task's env/compose tests already build, alongside the observed-ownership, missing-open-evidence, non-`COMPLETE`-open, wrong-mint, and wrong-memo regressions. The ownership-changed-during-signing regression resolves a real matching production binding (real isolated child setup, real candidate transaction built to that binding's own template) so `beforeSign`'s owner-refresh check -- gated on a binding actually having resolved -- genuinely executes, asserting both finalized-owner reads, the provider call, and zero sign/submission calls; a matching-owner positive control using the identical binding/setup/candidate proves the same fixture otherwise reaches the signer.
- The real `bin/hookemon-runner.mjs` entrypoint constructs the isolated Keychain child setup itself (`applySyntheticIsolatedChildSetup`) once `readEnvironment` reports the `synthetic-offline` authority; an isolated CLI launch needs only the documented `HOOKEMON_*` environment (including `HOOKEMON_COLLECTOR_SYNTHETIC_ROOT`), never in-process config surgery, an injected adapter, or test-only mutation capability. Every test in `collector-production-boundary-env.test.mjs` now builds its config through this real overlay rather than a manual test overlay, and a dedicated test spawns two genuinely separate `node` processes against the same isolated root, confirming both reopen the identical wrapper path and ephemeral identities.
