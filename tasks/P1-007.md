# P1-007 — Fund one payout commitment

## TASK

Implement one atomic payout commitment that accepts exact attributable returned USDG only from the immutable `PegCycleVault` of an existing returned cycle, binds a unique payout identifier to one canonical fixed-depth Merkle-sum root, and isolates the resulting fully backed liability permanently.

## RELEVANT FILES

- `architecture/interfaces.json` — Frozen shared cycle, accounting, token, and exact vault-to-hook payout interfaces.
- `packages/contracts/src/process/IPegCycleVault.sol` — Exact payout-authorization tuple and hook-only consumption interface.
- `packages/contracts/src/process/PegCycleVault.sol` — Immutable cycle identity, returned-proceeds custody, exact payout authorization, terminal failure, and vault-only funding authority.
- `packages/contracts/src/payout/CanonicalMerkleSum.sol` — New depth-10 proof-domain, checked-sum, padding, and root-verification library.
- `packages/contracts/src/payout/PayoutCommitment.sol` — New atomic funding, immutable payout identity, liability accounting, and conservation component.
- `packages/contracts/test/payout/PayoutCommitment.t.sol` — New funding, mutation, proof-domain, conservation, solvency, reentrancy, and forbidden-surface tests.
- `packages/contracts/tooling/payout/canonical-merkle-sum.mjs` — New independent non-Solidity manifest, tree, and proof reference implementation.
- `packages/contracts/test-js/payout/canonical-merkle-sum.test.mjs` — New cross-language vectors for every domain field, tree position, padding rule, checked sum, and malformed proof.
- `packages/contracts/test-vectors/payout/canonical-merkle-sum-v1.json` — New deterministic shared vectors reproduced independently by Solidity and JavaScript.
- `docs/modules/payout-commitment.md` — Payout-commitment contract card that must describe the implemented interface, invariants, commands, and recovery path.

## PATTERN TO FOLLOW

Follow `docs/modules/payout-commitment.md`, `decisions/ADR-0014-sum-bound-permissionless-payouts.md`, `decisions/ADR-0019-immutable-peg-cycle-custody.md`, and `architecture/trust-boundaries.md` boundary `TB-16`. Build the canonical manifest and Merkle-sum domain exactly as `REQ-payout-commitment-3` specifies, reproduce it independently in Solidity and JavaScript, and accept funding only from exact measured vault and hook USDG deltas.

## CONSTRAINT

`P1-006` must be complete before this task starts. Only the exact immutable vault of the referenced returned cycle may fund through `fundPayoutFromPegCycle(PayoutAuthorization)`. The authorization binds revision, chain, hook, vault, USDG, historical Operations trigger, binding manifest, cycle, payout, distribution manifest/root/sum, stored return action, nonzero return receipt, expiry, and a single-use nonce. Funding must equal the positive root sum exactly, consume the exact stored authorization before expiry, leave vault USDG at zero, and credit the matching hook liability atomically. Operations is metadata only; no Operations or external-wallet payer/allowance path exists. `FAILED` is absorbing, and only `PAYOUT_COMMITTED` permits another cycle. The payout ABI must not contain ranking, LP, marketplace, route, cutoff, batch, delay, recipient replacement, surplus recovery, or arbitrary-recipient behavior. One global money-path lock must cover every external USDG call.

## ACCEPTANCE CRITERIA

- `REQ-payout-commitment-1` and `REQ-payout-commitment-2`: current-versus-cycle-bound caller and payer, unknown cycle, zero field, identifier replay, field mutation, false-return, revert, malformed-return, short-delta, excess-delta, direct-transfer, and reentrancy vectors prove atomic exact funding and permanent event-to-storage identity with no partially funded payout.
- `REQ-payout-commitment-3` and `REQ-payout-commitment-5`: independent Solidity and JavaScript builders reproduce identical canonical manifest bytes, digest, depth-10 root, root sum, padding, and all 1,024 proofs; every altered tag, schema, domain field, encoding, index bit, sibling, level, sum, order, depth, duplicate position, or overflow fails, and ABI scans expose only the minimal algorithm-neutral payout fields.
- `REQ-payout-commitment-4` and `REQ-payout-commitment-6`: stateful invariant fuzzing covers at least 100,000 mixed fee, release, funding, payment, retry, failure, and direct-transfer sequences with `funded = paid + unpaid`, global solvency, strict cross-payout isolation, and zero privileged sweep, rescue, withdrawal, or arbitrary-recipient path.
