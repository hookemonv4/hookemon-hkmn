# P2-008 — Bind distribution to cycle escrow

## TASK

Bind return reconciliation and payout authorization to the exact active cycle escrow instead of a shared coordinator balance.

## RELEVANT FILES

- `packages/runner/src/distribution/reconcile.mjs` — Finalized attributable return reconciliation into the named cycle escrow.
- `packages/runner/src/cycle/vault-payout-authorization.mjs` — Revision-57 payout authorization validation and encoding.
- `packages/runner/test/distribution/reconcile.test.mjs` — Wrong-account, contamination, and exact-delta vectors.
- `packages/runner/test/distribution/manifest.test.mjs` — Manifest integration with cycle-scoped reconciliation.
- `packages/runner/test/cycle/vault-payout-authorization.test.mjs` — Authorization schema, digest, and ABI vectors.
- `packages/runner/test/integration/phase-one-local-loop-adapter.mjs` — Local loop adapter using the cycle escrow.

## PATTERN TO FOLLOW

Follow `docs/modules/cycle-runner.md`, `docs/modules/payout-commitment.md`, and the exact finalized-delta reconciliation pattern. Treat the coordinator and each cycle escrow as distinct identities.

## CONSTRAINT

The compiler is deterministic and offline. Quotes, API status, insured value, gross conversion, coordinator balance, another escrow, unrelated transfers, or Operations custody cannot become attributable returned USDG.

## ACCEPTANCE CRITERIA

- Reconciliation binds one finalized return to the frozen cycle's distinct return account and rejects coordinator, Operations, policy, hook, zero, or another cycle's account.
- Payout authorization uses requirements revision 57 and reproduces the exact cycle-escrow-bound ABI and digest.
- The local loop routes return and payout evidence through the active cycle escrow without changing recipient, root-sum, or holder-settlement rules.
