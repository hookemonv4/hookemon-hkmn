## PATTERN TO FOLLOW

Follow `docs/modules/cycle-runner.md`, `docs/modules/provider-binding.md`, `REQ-cycle-runner-1`, and the exact schemas frozen by `P1-001`. Record intent before every possible mutation, independently decode complete generated transactions, and reconcile provider state plus finalized chain state before retrying.

## CONSTRAINT

Thin V1 supports one operator-selected current pack, quantity one, non-turbo mode, one approved policy-controlled Solana execution wallet, standard open, standard eligible buyback, and one exact outbound and return route between immutable PegCycleVault custody endpoints. The runner reads current pack facts directly and freezes the selection into the cycle authorization. Operations is a trigger only and never an external recipient, return recipient, or payout funder. An Operations-controlled EOA is not permitted as any EVM, Solana, NFT, buyback, or return recipient. The immutable authorizer must differ from Operations, treasury, Programmable, hook, and vault. It contains no scheduling, catalog persistence or refresh, control-plane state, continuous operation, route discovery, quote engine, generic provider adapter, automatic retry, alternate recipient, or signing secret. Credential access, API mutation, signing, broadcast, conversion, asset transfer, and gas spend each remain ask-first and require an exact unconsumed owner authorization.

## ACCEPTANCE CRITERIA

- `REQ-cycle-runner-1`: deterministic fixtures cover the complete vault outbound, generate, purchase, status, open, NFT custody, post-open authorization, buyback, refund, vault return, and closure sequence with exact bound fields, decoded messages, finalized deltas, and globally unique receipt-consumption keys.
- `REQ-cycle-runner-1`: crash or restart at every journal boundary, blind retry, API replay, stale blockhash, changed instruction, wrong signer or destination, blocked wallet, partial signature, pending finality, duplicate receipt, unresolved NFT, short refund, and alternate-recipient vectors fail closed without duplicate action.
- `REQ-process-budget-4`: every prepared external action verifies one domain-separated owner authorization bound to release, cycle, action, programs or contracts, message digest, destination, asset, amount, minimum receive, principal and gas caps, nonce, attempt, and expiry; fixture mode proves behavior without accessing a secret or performing an external write.
- Recipient and authorization vectors reject an Operations-controlled EOA at every EVM, Solana, NFT, buyback, and return recipient field and reject an authorizer equal to Operations, treasury, Programmable, hook, or vault.
