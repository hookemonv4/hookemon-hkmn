# P2-012 — Recover stale operator state locks

## TASK

Recover a durable operator-state lock only when its canonical owner record names a process that definitely no longer exists.

## RELEVANT FILES

- `packages/runner/src/operator/state-file.mjs` — Canonical lock ownership, stable file checks, stale-owner detection, and exclusive reacquisition.
- `packages/runner/test/operator/state-file.test.mjs` — Lock ownership, recovery race, symlink, corruption, and replacement-owner regressions.
- `docs/modules/phase-boundary.md` — Local operator recovery boundary.
- `qa/reviews/phase2-operator-control-local-verification.json` — Local-only remediation evidence.

## PATTERN TO FOLLOW

Follow the existing canonical JSON, mode-0600, inode-stability, and compare-before-remove rules used by durable operator state.

## CONSTRAINT

Never remove a live, malformed, replaced, permissive, non-regular, or symlink lock. Recovery grants no production authority.

## DEPENDENCIES

- `P2-010` Anchor frozen cycle execution.

## REQUIREMENTS

- `REQ-cycle-control-1` at requirements revision 57.

## ACCEPTANCE CRITERIA

- A lock binds an exact positive PID and UUID token in canonical JSON plus one newline.
- A stable lock owned by a process that definitely exited is removed and reacquired exclusively; concurrent recovery has one winner.
- Live, corrupt, replaced, permissive, non-regular, and symlink locks remain fail-closed.
