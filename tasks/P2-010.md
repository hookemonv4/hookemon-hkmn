# P2-010 — Anchor frozen cycle execution

## TASK

Cryptographically anchor the frozen cycle plan to a fixture-only `computeCycleEscrow` observation and bind every journaled action to the complete plan and execution identity.

## PATTERN TO FOLLOW

Follow the existing fixture-only signed evidence pattern, canonical digest functions, and append-only journal recovery rules. Verification derives trust from a pinned Ed25519 public key, not a caller-provided expected address or boolean assertion.

## CONSTRAINT

The observation is fixture evidence only and grants no production RPC, signer, credential, broadcast, or mutation authority. An inactive expired frozen plan cannot start; an already active cycle remains recoverable after expiry.

## ACCEPTANCE CRITERIA

- One exact signed fixture `computeCycleEscrow(bytes32)` observation is verified with pinned Ed25519 authority, and no input field can self-assert the expected return address.
- Journal event zero, recovery, and every request and action bind the plan digest, pack-snapshot digest, and complete cycle execution binding; any substitution fails before mutation.
- Start rejects an expired inactive plan, while resume and reconciliation retain liveness for the same already-active expired cycle.
